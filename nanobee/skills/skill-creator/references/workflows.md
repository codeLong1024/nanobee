# 工作流设计参考

多步骤流程和条件逻辑的最佳实践，用于设计技能中的顺序工作流。

## 顺序工作流

适用于必须按固定顺序执行的步骤。

```markdown
## 工作流：处理用户上传的文件

### 步骤 1：文件验证
- 检查文件格式是否支持
- 检查文件大小是否在限制内

### 步骤 2：内容提取
- 根据文件格式选择提取方法
- 将提取结果保存为结构化数据

### 步骤 3：处理
- 根据用户需求处理提取的数据
- 执行分析、转换或生成

### 步骤 4：输出
- 将结果格式化为用户期望的输出
- 提供后续操作选项
```

## 条件分支

根据输入或中间结果选择不同路径。

```markdown
## 选择处理策略

根据用户需求类型选择路径：

- **提取文本** → 步骤 A（解析 + 文本提取）
- **转换格式** → 步骤 B（格式检测 + 转换 + 验证）
- **分析与统计** → 步骤 C（解析 + 分析 + 生成报告）
- **其他** → 向用户确认需求
```

## 循环/迭代

对多个输入重复相同的处理流程。

```markdown
## 批量处理

对每个输入文件：
1. 验证文件完整性
2. 执行处理逻辑
3. 保存结果到 `output/<文件名>`
4. 记录处理状态

处理完所有文件后，生成汇总报告。
```

## 并行路径

多个独立任务可同时执行。

```markdown
## 多维度分析

同时执行以下分析（顺序无关）：
- **数据分析**：读取数据文件，执行统计
- **文档分析**：提取文档结构，识别关键信息
- **代码分析**：检查语法，运行静态分析

完成后，汇总三个维度的结果。
```

## 决策树模式

适合基于多种条件选择路径的技能。

```markdown
## 文档处理决策树

1. 确定文件类型（.docx / .pdf / .xlsx / .md）
   - **.docx** → 使用 python-docx
   - **.pdf** → 使用 pdfplumber
   - **.xlsx** → 使用 openpyxl
   - **.md** → 直接读取
2. 确定操作类型（读取 / 转换 / 分析）
3. 执行对应操作
```

## 优雅降级

当首选方案不可用时，提供后备方案。

```markdown
## 获取网页内容

首选方案（一级 fallback）：
- 使用 web_fetch 工具获取

二级 fallback：
- 使用 readability-lxml 提取正文

三级 fallback（最后的兜底）：
- 使用 requests + BeautifulSoup 手动解析
- 告知用户结果可能不完整
```

## 设计原则

1. **明确每一步的输入和输出**：Agent 不需要猜测下一步该做什么
2. **提供明确的判断标准**：条件分支要有清晰的"何时走哪条路"
3. **包含异常处理**：失败时应重试、跳过还是终止
4. **保持步数合理**：单技能工作流不超过 7±2 步，超过则提取为子流程
5. **为 Agent 留自由裁量权**：不是所有步骤都需要硬编码，允许 Agent 在框架内进行判断
